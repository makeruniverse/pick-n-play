## Access

  `fe80::8aa2:9eff:fe10:d6b3%en8` (USB LAN adapter on the Mac = `en8`). The
  `%` in `~/.ssh/config` has to be escaped as `%%`.
- `ssh picknplay` (WiFi, 172.22.1.2) is not reliable: in netplan, `eth0` has
  the same static IP as `wlan0`. `docs/operation.md` says "DHCP", which is
  out of date.
- **The Pi has no internet** (github.com doesn't resolve). `pnp-update.timer`
  pulls nothing, and pushing to origin/expo does NOT reach the Pi. The Pi's
  wall clock is off too, so the `ts` columns in the DB are wrong. Differences
  between rows are correct (`events.t` is monotonic).

## Deploying (proven method)

Work in a worktree on branch `detect-robust` (= GitHub `expo`), then:

```sh
git push origin <branch>                                             # GitHub backup
git push pnp-messe:picknplay <branch>:refs/remotes/origin/pending    # onto the Pi, not active yet
# only after "jetzt":
ssh pnp-messe 'cd picknplay && git merge -q --ff-only origin/pending && sudo systemctl restart pnp-expo && sleep 8 &&
  if [ "$(systemctl show -p NRestarts --value pnp-expo)" = 0 ] && systemctl is-active -q pnp-expo &&
     ! journalctl -u pnp-expo --since "-9s" -o cat | grep -q Traceback;
  then git update-ref refs/remotes/origin/expo HEAD; echo "OK $(git log --oneline -1)";
  else git reset -q --hard <LAST_GOOD>; sudo systemctl restart pnp-expo; echo ROLLED BACK; fi'
git push origin <branch>:expo                                        # after OK
```

Running and last-known-good: **da20f23** (Pi HEAD = GitHub expo =
detect-robust). The one before: d10d6b1.

  params on gray + on G, union of the results. Two instead of three, because
  the game hit 2 cores next to teleop (now ~1.3). Crop to `TRAY_ROI` is in
  place.
- **Treats:** `VALUES` down to 8. Out: bonbon #4, cup_mini #10,
  cup_blaubeer #11 (green goes as dark as the code under the hall light). #5
  (red round) was never checked inside the frame.
- **Camera:** top exposure 200, gain 100 (`cam.json`, set with `pnp-cam`).
  The panes are brightened only for display (`PNP_VIEW_GAMMA`, default 0.55).
- **Game flow:** the tutorial always comes for new players. The idle screen
  shows `PLAYER #N` and `▶ PLAY` in the footer. After Bella, Oskar's order
  is a think-time screen: no panes, a large price ladder, a fuse and a
  countdown (`THINK_SECONDS` = 20, `pnp-think`), then the round starts by
  itself (▶ starts it earlier).
- **Reading screens (branch `ux-lesescreen`, NOT live yet):** new players
  get an announcement first ("up next: practice, doesn't count" + the camera
  rule: the arm must not block the camera), then practice with a fuse
  (`TUT_SECONDS` = 30, `PNP_TUT_SECONDS`; on timeout it goes on to the order).
  Oskar's order is its own phase `read` (no clock, 2 pages, ▶ READY),
  then the think time (`order`) with a single line. `tut_intro`/`read`
  fall back to idle after `READ_TIMEOUT` = 30 s without a button. New
  events: `think` (with `read` = seconds spent reading), `tut_timeout`,
  `quit why=idle`.
- **Hints** (`balance.next_move`): the first step of a shortest path (BFS
  over all trays) instead of greedy. Greedy used to lead into 3+ moves.
- **Name entry skipped** (from the other session, "game queue
  optimization"): ▶ → the player is named `#<no>`, ▼ → list of all numbers.
  `PNP_ASK_NAME=1` brings the name entry back.
- **Logging:** table `events` in `scores.db` (scene, round, tut_done/skip,
  order, play, tray, hint, quit, end, lang) with phase, scene clock and JSON.
